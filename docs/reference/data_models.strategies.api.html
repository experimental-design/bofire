MoboStrategy

data_models.strategies.api.MoboStrategy()

Multi-objective Bayesian optimization that maximizes the hypervolume improvement.

The hypervolume is the region dominated by the Pareto front and bounded by a reference point; each batch is chosen to enlarge it the most. The cost grows quickly with the number of objectives; with many objectives or large batches, QparegoStrategy is cheaper.

Examples

>>> MoboStrategy(domain=domain, ref_point={"yield": 0.5, "cost": 10.0})

MultiFidelityVarianceBasedStrategy

data_models.strategies.api.MultiFidelityVarianceBasedStrategy()

Single-objective Bayesian optimization that also chooses the fidelity at which to run each candidate (Kandasamy et al., 2016; Folch et al., 2023).

The candidate is chosen for the target fidelity; it is then run at the cheapest fidelity at which the model is still uncertain enough about it, so cheap experiments are used as long as they are informative. Needs a categorical task input with exactly one target fidelity, and a multi-task GP for every output.

Examples

>>> MultiFidelityVarianceBasedStrategy(domain=domain, fidelity_thresholds=0.1)

SoboStrategy

data_models.strategies.api.SoboStrategy()

Single-objective Bayesian optimization, of one objective or of several combined into one by a scalarization.

Without a scalarization, exactly one output has an objective to optimize; further outputs may have constrained objectives, such as sigmoid ones, which act as constraints the candidates should satisfy. With qLogPF as acquisition function, the strategy ignores the objectives and only searches for candidates that satisfy those constraints.

Examples

>>> SoboStrategy(domain=domain, acquisition_function=qLogEI())
>>> SoboStrategy(domain=domain, scalarization=WeightedScalarization())

WeightedScalarization

data_models.strategies.api.WeightedScalarization()

Combines several objectives by a weighted product and a weighted sum.

The objectives of the outputs in additive_features are summed, the others multiplied, each weighted by its weight; the weights are normalized to sum to 1. With multiplied objectives f1 and f2 and summed objectives f3 and f4, the scalarization is

f1^w1 * f2^w2 * (1 + w3 * f3 + w4 * f4)

so a candidate is only good if every multiplied objective is good, while the summed ones can make up for each other. Without additive_features this is a weighted geometric mean; with all objectives in additive_features, a weighted sum. Multiplied objectives have to be non-negative: minimize and close-to-target objectives can only be summed, and a maximize objective, or a desirability without clipping, is only non-negative within its bounds.

Examples

>>> WeightedScalarization(weights={"yield": 2.0})
>>> WeightedScalarization(additive_features=["yield", "cost"])

LLMStrategy

data_models.strategies.api.LLMStrategy()

Strategy that uses a large language model to propose optimization candidates.

Instead of fitting a surrogate and optimizing an acquisition function, this strategy lets an LLM read the optimization problem — feature bounds, constraints, objectives, contextual descriptions, and prior experiments — and directly propose candidate points. It is useful for cold-start designs, mixed / categorical / molecular spaces where domain knowledge helps, and exploration informed by written context (Feature.context and Domain.context).

It is not a replacement for a Bayesian optimizer on well-understood numerical problems: there is no calibrated uncertainty model and no acquisition function. Treat candidates as informed heuristics, not optima.

On each ask(), a pydantic output schema is generated from the domain’s input features and the LLM is prompted with a textual problem description plus, optionally, a selection of prior experiments. Returned candidates are validated against the domain; bound or constraint violations are sent back to the LLM as retry messages via pydantic-ai’s output_retries.

Currently supports single-objective optimization with MaximizeObjective or MinimizeObjective, and LinearEquality, LinearInequality, and NChooseK constraints. All feature types are supported.

Example

Basic usage::

strategy = LLMStrategy.make(
    domain=domain,
    llm=AnthropicLLMProvider(model="claude-sonnet-4-5"),
)

Enable extended reasoning for harder problems (many constraints, rich context). thinking is pydantic-ai’s cross-provider capability key — it maps to Anthropic’s extended thinking, OpenAI’s reasoning_effort, and similar mechanisms on other providers. Reasoning increases cost and latency considerably, so it is not enabled by default::

strategy = LLMStrategy.make(
    domain=domain,
    llm=AnthropicLLMProvider(model="claude-sonnet-4-5"),
    model_settings={"thinking": "high"},
)

Attributes

Name Type Description
llm AnyLLMProvider LLM provider configuration.
model_settings Optional[Dict[str, Any]] Optional dict forwarded directly to pydantic-ai’s model_settings. Useful keys include temperature, max_tokens, top_p, seed, timeout, and the cross-provider capability thinking ("low" / "medium" / "high"). Provider-prefixed keys such as anthropic_thinking or openai_reasoning_effort are also accepted as escape hatches for finer control. Keys are not validated by BoFire — pydantic-ai and the underlying provider SDK are the source of truth.
output_retries PositiveInt Number of retries when output validation fails (constraint or bound violations). Each retry sends the LLM the invalid candidates and the error so it can correct.
n_recent_experiments Optional[Annotated[int, Field(gt=0)]] If set, only the most recent N experiments are shown to the LLM. Keeps prompt size bounded on long campaigns.
n_top_experiments Optional[Annotated[int, Field(gt=0)]] If set, the top N experiments by objective value are shown to the LLM. Combine with n_recent_experiments to mix recency and quality.
system_prompt Optional[str] Optional override for the default system prompt.

### MultiFidelityVarianceBasedStrategy { #bofire.data_models.strategies.api.MultiFidelityVarianceBasedStrategy }

```python
data_models.strategies.api.MultiFidelityVarianceBasedStrategy()
```

Single-objective Bayesian optimization that also chooses the fidelity at
which to run each candidate (Kandasamy et al., 2016; Folch et al., 2023).

The candidate is chosen for the target fidelity; it is then run at the cheapest
fidelity at which the model is still uncertain enough about it, so cheap
experiments are used as long as they are informative. Needs a categorical task
input with exactly one target fidelity, and a multi-task GP for every output.

### WeightedScalarization { #bofire.data_models.strategies.api.WeightedScalarization }

```python
data_models.strategies.api.WeightedScalarization()
```

Combines several objectives by a weighted product and a weighted sum.

The objectives of the outputs in `additive_features` are summed, the others
multiplied, each weighted by its weight; the weights are normalized to sum to 1.
With multiplied objectives f1 and f2 and summed objectives f3 and f4, the
scalarization is

    f1^w1 * f2^w2 * (1 + w3 * f3 + w4 * f4)

so a candidate is only good if every multiplied objective is good, while the
summed ones can make up for each other. Without `additive_features` this is a
weighted geometric mean; with all objectives in `additive_features`, a weighted
sum. Multiplied objectives have to be non-negative: minimize and
close-to-target objectives can only be summed, and a maximize objective, or a
desirability without clipping, is only non-negative within its bounds.

#### Examples {.doc-section .doc-section-examples}

```python
>>> WeightedScalarization(weights={"yield": 2.0})
>>> WeightedScalarization(additive_features=["yield", "cost"])
```

### LLMStrategy { #bofire.data_models.strategies.api.LLMStrategy }

```python
data_models.strategies.api.LLMStrategy()
```

Strategy that uses a large language model to propose optimization candidates.

Instead of fitting a surrogate and optimizing an acquisition function,
this strategy lets an LLM read the optimization problem — feature bounds,
constraints, objectives, contextual descriptions, and prior experiments —
and directly propose candidate points. It is useful for cold-start
designs, mixed / categorical / molecular spaces where domain knowledge
helps, and exploration informed by written context (``Feature.context``
and ``Domain.context``).

It is not a replacement for a Bayesian optimizer on well-understood
numerical problems: there is no calibrated uncertainty model and no
acquisition function. Treat candidates as informed heuristics, not
optima.

On each ``ask()``, a pydantic output schema is generated from the
domain's input features and the LLM is prompted with a textual problem
description plus, optionally, a selection of prior experiments. Returned
candidates are validated against the domain; bound or constraint
violations are sent back to the LLM as retry messages via pydantic-ai's
``output_retries``.

Currently supports single-objective optimization with ``MaximizeObjective``
or ``MinimizeObjective``, and ``LinearEquality``, ``LinearInequality``,
and ``NChooseK`` constraints. All feature types are supported.

#### Example {.doc-section .doc-section-example}

Basic usage::

    strategy = LLMStrategy.make(
        domain=domain,
        llm=AnthropicLLMProvider(model="claude-sonnet-4-5"),
    )

Enable extended reasoning for harder problems (many constraints,
rich context). ``thinking`` is pydantic-ai's cross-provider
capability key — it maps to Anthropic's extended thinking, OpenAI's
``reasoning_effort``, and similar mechanisms on other providers.
Reasoning increases cost and latency considerably, so it is not
enabled by default::

    strategy = LLMStrategy.make(
        domain=domain,
        llm=AnthropicLLMProvider(model="claude-sonnet-4-5"),
        model_settings={"thinking": "high"},
    )
